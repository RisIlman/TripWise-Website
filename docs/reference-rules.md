# TripWise reference rules

The source of truth is the completed [TripWise Python application](https://github.com/RisIlman/TripWise-Budget-Tracker/tree/main). Local `AGENTS.md` defines the web flow and destination research requirements. `TripWise_Web_Overview.md` and the original planning PDF were absent during implementation.

## Calculation mapping

| Python | Web |
| --- | --- |
| `pricing.py` | `src/data/pricing.js`, `src/domain/pricing.js` |
| `trip.py` | `src/domain/validation.js` |
| `expenses.py` | `src/domain/expenses.js` |
| `itinerary.py` | `src/domain/itinerary.js` |
| `summary.py` | `src/domain/summary.js` |

All amounts are RM estimates. Accommodation is per person per night; local transport, meals and miscellaneous spending are per person per day. Return airfare is per person per round trip from KLIA. Nights equal days minus one. All category totals multiply by the traveller count.

ASEAN countries determine accommodation, local transport and airfare multipliers. Other destinations use their region. Meal and miscellaneous suggestions use the region. Only airfare changes by season: Low 0.85, Normal 1.00, Peak 1.40.

Meals and miscellaneous support suggested, positive percentage increase, positive percentage decrease up to 100%, and non-negative custom amounts. Invalid or non-finite inputs and overflowing totals are rejected. Total and remaining balance use Python-compatible binary-float rounding to two decimal places, including ties to even. Per-person figures divide group figures by traveller count.

The three states are WITHIN BUDGET, EXCEEDING BUDGET and AT BUDGET LIMIT. Over-budget estimates identify the largest category. Only scheduled attractions contribute ticket costs.

## Scheduling

Initial scheduling sorts attractions by area, then Morning / Afternoon / Evening. Placement searches for: same area with preferred slot; same area with any free slot; earliest day with preferred slot; any free slot. Slots represent 9:00 AM, 2:00 PM and 5:00 PM. Unspecified areas do not count as a same-area match.

The initial list is scheduled when the traveller chooses Build my schedule. Subsequent additions use the placement rules without moving existing entries. Occupied move targets are rejected. Shortening a trip moves displaced entries to the unscheduled list and removes their ticket costs; extending it again does not silently reschedule them. Days render in batches of seven.

## Research and persistence

The map is an original schematic regional illustration, not a geographic boundary dataset. Its selections match the labelled selector. ASEAN country options exactly match Python; other countries remain a text input. Malaysia and blank country names are rejected.

`src/data/destinations.js` intentionally starts empty. Add only researched records with country, focus assignments, source URLs and research date. Place selections do not affect calculations. Attractions are entered separately with a traveller-supplied ticket price.

Changing region or country clears invalid child destination selections and retains unrelated inputs. Manual itinerary entries remain editable. A versioned browser-local draft stores inputs and attractions; totals are derived. Corrupt drafts fall back to an empty trip; unavailable storage is explained in the interface. There is no account, server database, live-price service or actual-spending ledger.

## Verification

`tests/fixtures/pythonExpectedResults.json` contains outputs generated by executing the original Python pricing, expense, scheduling and summary functions. SHA-256 hashes record the Python file contents. Fixtures cover Thailand and France, every season, suggested expenses, percentage overrides and custom expenses including zero. Schedule fixtures cover same-area placement, fallback order, full capacity and overflow.

Regenerate against a checkout of the Python repository:

```sh
python3 tests/fixtures/generate_reference.py /path/to/TripWise-Budget-Tracker
```

Unit tests cover parity, validation, all budget states, moves and shortened trips. Playwright covers keyboard interactions on desktop and mobile viewports, storage, validation, pricing-guide return, rescheduling and removal.
